# 任务：库存感知做市报价

## 工程背景

做市商在流动性较低的 DUAL 品种上持续发布买卖报价，同时使用流动性较高的主市场作为带噪声
的公允价值参考。有竞争力的报价可以赚取价差并提供流动性，但知情订单往往会在价格向不利方向
变化前成交。策略需要随着波动率、订单流、DUAL 盘口和库存的变化，动态调整报价宽度、偏移和数量。

三个合成品种对使用 NVDA、JPM 和 AMZN 作为标签。这些名称只用于场景标识；benchmark 不包含
真实行情，也不会连接交易所。

## 市场模拟器

每个场景运行240步。潜在公允价值服从相关对数价格过程：

```text
F[t+1] = F[t] * exp(sigma[t] * z[t])
```

价格冲击由全市场、单资产和持续订单流成分共同构成。市场会在平静、普通、高波动和高毒性流动性
状态之间，以确定性的伪随机分段方式切换。策略不能直接看到潜在状态标签，只能通过价格、波动率
估计、订单不平衡、流动性、不利选择，以及只说明当前操作约束的做市台指令进行判断。

主市场和 DUAL 共享潜在公允价值，但具有独立观测噪声和均值回复的 DUAL basis。候选报价偏移先
转换为围绕主市场中价的价格，再根据其相对 DUAL 同侧最优报价的竞争力计算被动成交概率。穿过
DUAL 价差的可成交报价按 DUAL 对手方最优价立即成交并支付 taker 费用；被动成交按候选价格执行，
支付较低的 maker 费用。

所有价格冲击、状态切换、basis 创新、订单到达、成交随机数和市场单数量都在策略运行前生成。
候选策略和 anchor 因而重放完全相同的外生路径。策略只会改变成交、现金和库存，不能改变未来随机性。

## 评测场景

评分器使用20个确定性场景：

- 12个开发场景，提供逐场景详细反馈；
- 8个验证场景，组合新的波动率、持续/反转订单流、DUAL basis 变化和订单到达强度。

验证场景完整参与可行性与评分，但只返回汇总反馈。这样既能测试策略是否能泛化到详细反馈之外的
市场组合，又能保证结果完全可复现、不同 Agent 可以公平比较。由于 verifier 是开源的，这不等于
声称测试数据在密码学意义上不可见。

## 观察

`decide_quotes(observation)` 接收：

- `step`、`time_fraction` 和 `position_limit`；
- 每个资产的 `primary_bid`、`primary_ask`、`dual_bid`、`dual_ask`；
- 当前 `dual_inventory`；
- 指数加权 `volatility` 估计；
- `[-1, 1]` 范围内的指数加权 `order_imbalance`。
- 每个资产一条自然语言 `desk_mandate`，由流动性支持、毒性流防御、库存回收等指令组合而成。

策略必须把这些指令转化为报价行为。固定的一组数值动作无法同时满足所有组合：流动性支持要求
每个激活侧至少展示2手，而毒性流警报要求每个激活侧最多1手且只能挂 maker 单；库存回收指令
还会增加非对称限制。观察中不包含潜在市场状态标签、场景名称、随机种子、未来价格、未来订单流
或未来成交随机数。

## 动作接口

在 `scripts/init.py` 中实现：

```python
def decide_quotes(observation) -> dict:
    ...
```

每个基础品种返回：

- `bid_offset_bps`、`ask_offset_bps`：相对主市场中价的距离，范围 `[1, 80]` 基点；
- `bid_size`、`ask_size`：整数展示数量，范围 `[0, 5]`。

数量为0表示本步关闭该侧报价。由于每个场景都会启动全新的 worker，`reset_policy()` 是可选接口。
策略必须是确定性的，返回值必须能够序列化为 JSON。

## 候选进程边界

候选代码在独立的持久子进程中加载。父评分器每步只发送公开观察并接收 JSON 动作。加载、每次决策
和整个场景都有时间限制；候选标准输出会被隔离，模型/API 凭据不会传入其环境。这可以阻止候选修改
父评分进程，或通过父进程调用栈读取未来 tape。它不是针对恶意原生代码的通用操作系统安全沙箱。

## 硬可行性约束

- 每个 DUAL 库存必须始终位于 `[-50, 50]`。
- 每个必需品种和字段都必须存在且为有限数。
- 数量必须是整数（布尔值也会被拒绝）；偏移和数量必须在范围内。
- 必须遵守当前做市台指令：流动性支持要求激活侧至少2手；毒性流警报要求最多1手且不得穿过
  DUAL 盘口；库存回收会限制增加风险的一侧，并要求降低库存的一侧保持激活。
- 每个场景至少70%的报价侧必须处于激活状态。
- 每个场景的流动性服务不得低于0.20。服务分奖励展示数量，并随报价落后于当前 DUAL 最优价的
  距离指数衰减。
- 账户初始拥有100,000单位现金；需要借入现金的买入会被拒绝。
- 允许受限负库存，代表普通做市空头库存；借券、保证金和融资费用不在本模拟器范围内。

任何硬约束失败都会令 `valid=0` 且正式排名分 `combined_score=0`。独立的
`diagnostic_score` 仍保持连续，使优化器能够判断无效设计是否有所改善。
产物会按类别报告违规次数，例如 `schema_missing_field`、`range_offset`、
`mandate_maker_only` 和 `risk_position_limit`，从而明确区分结构错误、数值越界和风险违规。

## 目标与评分

每个场景的经济目标为：

```text
J = PnL
    - 0.55 * 最大回撤
    - 1.00 * 库存RMS
    - 0.80 * 库存风险RMS
    - 1.50 * 期末平仓成本
    - 违规与流动性不足惩罚
```

PnL 已包含 maker/taker 费用，并按 DUAL 中价标记库存。库存风险项使用价格和当前单步波动率缩放
持仓；期末平仓成本使用 DUAL 半价差加 taker 费用。

候选策略与一个可行的固定18基点 anchor 在同一 tape 上比较。平滑 `tanh` 映射产生 `[0, 100]`
范围的逐场景分数，anchor 为50。连续诊断分为：

```text
diagnostic_score = 0.75 * 场景分数均值
                 + 0.25 * 场景分数第20百分位
```

该指标既奖励平均表现，也会惩罚在少数状态下表现很差的策略。当且仅当20个场景全部可行时，
`combined_score = diagnostic_score`；否则 `combined_score = 0`。分数越高越好。

优秀策略需要根据可执行反馈逐步发现：有竞争力的 DUAL 报价、库存偏移、订单流响应、波动率感知
的宽度/数量，以及跨状态切换的稳健行为。本合成 benchmark 不是交易建议或投资产品。
